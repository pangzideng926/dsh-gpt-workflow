# DSH 受限管道兼容实验

本仓库仅用于独立验证，不安装到 DSH，不修改业务任务及全局 Node 配置。

## 目标与验收

1. Windows Low / WRITE_RESTRICTED 中原样运行默认 `node --test`，真正启动测试文件子进程；不得改成同进程测试。
2. 同步、异步、大数据、嵌套进程、worker、fork IPC 与失败退出均保持真实行为。
3. 工作区写入按模式允许；工作区外、只读模式写入仍拒绝，后代保持受限令牌。
4. 两个独立会话的私有临时目录不能互写，管道不能被另一受限会话写入；退出清理私有临时目录。
5. 缺少或伪造管道身份时关闭失败，不回退到不受限执行。

## 方案与适用边界

- 为每次独立运行器增加随机 IPC capability SID，只进入 restricting SID 列表，不授予任何目录权限；保持原有 flags=13 与 Low 完整性。
- 原生 Node-API 实验模块在当前 node.exe 的导入表中适配 CreateNamedPipeA/W；只针对 libuv 的当前进程管道名、FIRST_PIPE_INSTANCE、默认安全描述符。既有显式描述符不覆盖。
- 新管道显式 DACL 仅允许当前用户与本次 IPC SID，并带 Low 标签、拒绝远程客户端。不修改令牌默认 DACL，不放宽文件系统。
- 此适配用于验证上游 libuv 管道创建的最小改动，不是面向所有 Windows 程序的生产方案。后续正式接入应采用维护过的 libuv/运行时补丁，避免未经全面兼容测试的导入表适配。
- WRITE_RESTRICTED 是写入隔离：不会凭新增 SID 得到完整的跨会话读取保密性；必须区分拒绝跨会话写入与强 IPC 隔离。不能据本实验声称整个 DSH 是完整安全边界。

源自已安装 DSH 0.2.0-rc.2 的运行器副本，依赖只读引用安装包；准备脚本校验精确修改点。所有生成文件、二进制及实测记录位于 `.artifacts/`，不写入生产安装。
