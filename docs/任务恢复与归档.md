# 任务恢复、重试与归档

在 GPT 工作台点击任务卡片，进入详情操作；按钮随任务状态显示。

| 操作 | 行为 |
| --- | --- |
| 异常恢复 | 检查本任务的执行进程、接收状态及会话释放证据，修正已结束的异常状态；不会重新派发。 |
| 重试 | 规划失败沿用原请求和 GPT 会话，保存前次记录后重新规划；开发失败沿用原任务创建新轮次，保留旧方案、结果与证据。 |
| 清理重做 | 在确认无存活进程后，将旧异常记录、关联轮次及残留锁移入同卷 `trash/` 回收站目录，并按原需求立即重新提交 GPT 规划处理。 |
| 归档 | 从普通列表隐藏，保留任务、代码、历史及禅道关联，不删除文件。 |
| 恢复显示 | 在“已归档”中打开详情后恢复到普通列表，不启动开发。 |
| 删除任务 | 在确认无存活进程后，将任务记录、关联轮次及残留锁移入同卷 `trash/` 回收站目录并解除禅道旧关联，不直接物理删除文件。 |

失败任务通常先核对原因，再按需“异常恢复”→“重试”。进程尚在运行、会话未证明结束、仓库被占用时会拒绝操作；旧记录缺少进程证据时需在原会话核查，不能通过按钮强制解锁。待审查及需要返工的开发任务应先交回 GPT，重试不能代替审查。

重试开发前检查方案和代码快照。失败执行若改变提交或分支，或失败后代码又被修改，会停止并要求 GPT 重新核对，不能把当前内容自动认作安全基线。多仓库先全部检查，再启动失败/未启动项，不重新开发已通过项；中途失败保留各项真实状态。

执行中、成功及错误提示显示在详情顶部，不会被列表轮询清除；长错误可独立滚动查看。重复点击、过期页面会被拦截；网络超时后先查看刷新状态，不自动再次派发。归档与普通列表分别分页，超过 100 条可“加载更多任务”。禅道相同来源始终回到原关联，归档不会导致重复派单。

新版宿主接口需在任务空闲时完整重启 DSH 加载，刷新网页不等于更新宿主。此功能不会修复 Windows 沙箱的 `spawn EPERM`，原始环境问题未解决前重试仍可能失败。
